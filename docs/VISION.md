# Agents as fellow players

Minecraft gives people and agents a shared place to explore, make things and
learn to work together. An agent should be a recognizable participant: able to
notice what is happening, understand a request, make useful choices and carry
work through while people play. People should be able to change direction or
ask for help without supervising every step.

The adapter connects that participation to the actual world. Moving, gathering,
building and sharing materials should have ordinary survival consequences.
Agents need room to choose methods and coordinate, with enough evidence to
distinguish an intended result from what the server actually accepted. Fluent
conversation cannot substitute for a bridge that can be crossed or supplies
that reached the intended player.

A saved connection lets the same individual return to a world or participate in
another one without confusing the two places. A person should be able to bring
an agent along, temporarily disconnect it, and reconnect later without rebuilding
its identity or losing useful work. Setup, account linking and recovery are part
of that experience, including when a person joins from a different game client.

Other experiences can help people inspect the world, give direction and receive
results through the adapter's authorized interfaces. A voice conversation should
not need to invent a player identity, expose private conversation in public game
chat, or turn every observation into a spoken update. The game remains a place
to participate directly; external controls should make that participation easier.

These early implementations barely suggest the possible depth of the experience.
Existing dashboards, setup scripts and preview clients do not prescribe its
future UX. We should judge improvements by useful play and collaboration, the
effort needed to set up and recover, and how little people must repeat or rescue.
Evaluate physical results and conversation separately, then test them together.

This direction applies the [shared Constellation vision](https://github.com/microsoft/amplifier-constellation/blob/main/docs/VISION.md).
The [interface map](interfaces.md) locates the shared agreements and the
Minecraft-specific definitions that consumers can rely on. This vision does not
declare an unimplemented capability or a new protocol.
